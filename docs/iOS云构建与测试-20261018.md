# iOS云构建与朋友测试（Windows，无Mac）

> 最新交付请先阅读 [iOS基础版更新与构建-20261019](iOS基础版更新与构建-20261019.md)。本页保留旧流程参考，功能与验证数量以新版交接报告为准。

本次已准备苹果工程和Codemagic配置。你不用购买或借用Mac，可以在Windows浏览器里连接云端Mac完成编译。

当前完成的是源码准备和本地检查；尚未连接任何云构建账号，也未实际执行Xcode编译或iPhone真机测试。

## 先做这一步：无需苹果会员的编译检查

1. 注册GitHub账号，建立一个私有仓库。
2. 将交接源码压缩包解压，把里面的内容放到仓库根目录。根目录应直接看到codemagic.yaml和pubspec.yaml；不要只上传ZIP，也不要再套一层项目目录。
3. 注册Codemagic，用网页连接这个私有仓库，添加Flutter应用。
4. 选择工作流“iOS - 生成未签名 IPA（自行签名）”（ios-unsigned），手动开始构建。构建服务可能计入免费额度或产生费用，以账户当时套餐为准。
5. 第一次构建会安装依赖、运行代码检查和测试，再编译iPhone版本与模拟器版本。
6. 如果失败，保留失败步骤和日志供修复。只有云端构建成功，才能确认苹果原生依赖实际编译通过。

无需在第一条流程填写苹果账号、签名证书或API密钥。工作流没有自动触发，也没有自动上传或分发步骤。

### 第一条流程的产物

| 文件 | 用途 | 能直接安装到朋友的iPhone吗 |
| --- | --- | --- |
| my-accounting-app-unsigned.ipa | iPhone真机包，交给工具签名后安装 | 签名后才可安装，工具兼容性待实测 |
| SIMULATOR-only-not-for-iphone.zip | 仅供苹果模拟器运行 | 不能 |
| preflight.json | 工程配置检查结果 | 不是安装包 |

只有my-accounting-app-unsigned.ipa用于后续真机签名；模拟器ZIP和交接源码ZIP都不能用来给iPhone安装。云端步骤的成功状态、编译日志和产物共同用于判断是否编译通过；preflight.json仅代表编译前的源码检查。


### 用自己的工具签名安装（本次新增）

如果只是把测试版发给朋友签名安装，选择同一条“iOS - 生成未签名 IPA（自行签名）”工作流即可。它不需要在云构建服务填写苹果账号或签名私钥。云端完成真机编译后，在Artifacts中下载my-accounting-app-unsigned.ipa，再交给签名工具处理。

当前Windows电脑不能直接生成苹果原生二进制；本地源码ZIP也不能改后缀充当IPA。新增的是云端编译后的打包流程，现在还没有实际生成IPA或验证真机安装。

签名工具可按测试者条件选择：

| 工具 | 适用条件及取舍 |
| --- | --- |
| Sideloadly | 支持Windows，适合第一次用数据线给iPhone安装测试。免费苹果账号通常每7天续签，自动续签时需电脑与手机连接或在同一网络；新系统通常需开启开发者模式。 |
| AltStore Classic / AltServer | 支持Windows，通过电脑协助安装及续签；免费账号的应用同样有7天有效期。 |
| SideStore | 首次安装需电脑，后续可在手机上续签；免费账号仍需定期续签，设置步骤更多，需要其文档要求的Wi-Fi和本机VPN配置。 |
| TrollStore（巨魔） | 只支持部分旧系统。官方列出的范围为iOS 14.0 beta 2至16.6.1、16.7 RC（20H18）及17.0；不适合最新iOS。本应用最低iOS 15，因此不能在iOS 14上运行。 |

能否安装取决于手机的系统版本、签名方式及这次原生构建的实际结果，不能只根据“新款iPhone”判断。首次测试可先考虑Sideloadly，朋友自行在官方工具中登录自己的苹果账号，无需向开发者提供账号密码。

应用使用设备钥匙串保存本机加密密钥；首次签名和后续续签应保持相同苹果账号、应用标识和允许的钥匙串访问组。更换签名身份或卸载前导出完整备份并保存恢复码。具体工具对本应用的兼容性仍待真机验证。

## 可选：通过TestFlight向朋友分发

下面是选择苹果官方测试分发时使用的流程；选择自行签名安装的用户可以跳过这一节。

1. 开通Apple Developer Program，完成苹果要求的账号和身份验证。
2. 在Apple Developer和App Store Connect登记同一个应用标识，创建应用记录。预设标识是xyz.698239.myaccountingapp，正式登记前确认它可用。
3. 在Codemagic建立保密变量组appstore_credentials，设置下表中的四个Secret变量。
4. 手动选择“iOS - 签名打包（开发者账号就绪后）”（ios-signed）。它会自动配置证书，输出签名后的IPA，但不会自动上传、邀请测试者或提交App Store审核。
5. 确认签名包成功后，再按tools/ios/testflight-publishing.yaml.example准备测试分发。填写应用的测试说明、隐私信息和加密相关问题，建立Accounting Testers测试组，再启用TestFlight上传。
6. 首次对外测试按苹果要求提交测试审核，获准后发邀请链接给朋友。朋友安装TestFlight，接受邀请后安装测试。

| Secret变量名 | 含义 |
| --- | --- |
| APP_STORE_CONNECT_ISSUER_ID | 苹果API页面显示的Issuer ID |
| APP_STORE_CONNECT_KEY_IDENTIFIER | 苹果API密钥的Key ID |
| APP_STORE_CONNECT_PRIVATE_KEY | 苹果下载的.p8文件完整内容 |
| CERTIFICATE_PRIVATE_KEY | 长期保留、用于签名证书的RSA私钥 |

可以通过App Store Connect网页创建专用API密钥，权限按Codemagic文档选择App Manager。密钥在平台的保密变量中设置，不写入源码。

tools/ios/create_signing_key.cjs支持在Windows生成签名用RSA私钥。它要求保存到项目目录之外，并拒绝覆盖已有文件；等开发者账号就绪后再使用。该私钥与记账数据的加密恢复码是两种不同的东西。

签名工作流中的版本号由Codemagic项目构建计数生成。后续持续在同一个Codemagic项目更新此应用，应用标识确认后保持稳定。

## 已补齐的工程配置

- 应用显示名称：我的记账本。
- 最低系统：iOS 15.0，与所选Xcode 26.2支持的部署范围一致；安卓系统要求未改变。
- 固定Flutter 3.38.7，与当前本地SDK一致；云端使用Xcode 26.2。
- 补齐Podfile，以及Debug、Release、Profile对CocoaPods配置的引用。
- 使用当前版本插件已有的CocoaPods实现，云端关闭Swift Package Manager，避免两种依赖方式混用。
- 文件选择只保留文档导入、导出，不启用照片或音频媒体库选择器；语音录制由原有麦克风模块处理。
- 保留麦克风用途说明、固定收支的本地通知实现及设备本机钥匙串存储。
- 添加并链接PrivacyInfo.xcprivacy，说明文件元数据及应用偏好设置的使用原因。它不替代App Store Connect的隐私申报。
- 没有自动声明“无非豁免加密”；应用包含自行实现的加密，分发前须按实际功能完成苹果的加密相关问题。
- 保留现有图标；已检查图标文件数量、尺寸和1024像素图标格式。正式发布前仍可再确认应用图标设计。
- 记账和账户编辑页增加安全区域，避免底部操作被iPhone手势横条覆盖。
- 现有账单、账户余额计算、密钥保护和服务器配置没有在此流程中重写。

## 依赖来源与构建过程

本地pubspec.lock来自pub.flutter-io.cn。云端准备步骤只把锁文件中的镜像地址换成pub.dev，版本号和SHA校验值保持不变，然后使用flutter pub get --enforce-lockfile。

该规范化只发生在云端工作副本，不改变Windows项目原有镜像设置。没有依赖升级。
