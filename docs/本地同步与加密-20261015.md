# 本地同步与加密基础（2026-10-15）

项目：D:\Flutter\projects\my_accounting_app。

## 已完成

- 原有账单、统计、资产和离线记账界面保留；“我的”增加“同步加密与恢复码”入口。
- 本地数据库版本从 7 增至 8。仅新增内部元数据表，不改原有业务表字段与本机编号。
- 12 类业务表通过 36 个 SQLite 触发器捕获新增、修改、删除。覆盖账本、分类、资产、预算、标签、账单、标签关联、导入核对、固定收支及其应记记录、退款来源与事件。
- 待同步队列与业务修改在同一事务中提交；连续修改按对象合并，删除保留墓碑与稳定标识。
- 本地用户 ID 和数据库安装范围隔离密钥。首次初始化把旧业务记录纳入队列，账单空 user_id 尽量通过所属账本确定用户；无法确定归属的数据不会擅自分配给当前账号。
- 手机使用密码学安全随机数生成独立 256 位账单密钥与独立 256 位恢复秘密。恢复码带格式标识和校验码。
- AES-256-GCM 加密/解密模块对所有者、空间、对象、版本、规范化父版本和密钥代数做 AAD 绑定。支持加密删除标记，解密拒绝被篡改或错用对象的内容。
- 恢复秘密经 HKDF-SHA256 派生包裹密钥，再以 AES-GCM 加密账单密钥。恢复码不是普通密码，不经邮件发送，也不写入 SharedPreferences。
- 手机密钥和加密后的恢复包放在系统安全存储；iOS 使用仅此设备、解锁时可访问的 Keychain 项。用户确认保存恢复码后才提交，已有或损坏配置均阻止自动覆盖。
- 提供“校验恢复码”“本机加密自检”，不发送网络请求。

## 数据库与备份

新增 local_sync_control、local_sync_objects、local_sync_queue 三张内部表。队列只存标识和本地版本，不额外复制账单明文。当前本机业务数据库仍然采用原来的 SQLite 存储，这不是整库加密或应用锁。

完整备份继续只包含原有业务数据与允许的设置，便携备份 schema_version 仍为 7；物理数据库 version 8 新增的内部队列不进入备份，所以之前 V7 备份仍可按原校验逻辑恢复。密钥、恢复码、设备身份与队列都不会出现在完整备份中。

恢复在同一事务中暂停捕获，恢复业务数据后清理旧同步映射并重建，轮换安装范围。恢复失败会回滚数据、同步状态和安装范围。这样备份里的本机数字用户 ID 不会直接继承恢复前账号的密钥。

完整数据备份恢复与云端密钥恢复是不同流程：恢复业务备份后需重新建立本机加密配置；未来接通旧云空间时仍须通过可信设备或正确恢复码解锁，不能直接创建新密钥替换旧云密钥。旧安全存储条目不会在此阶段自动删除。

## 手机验证步骤

1. 先使用原版导出一份密码保护的完整备份，保留原 APK。使用保留数据的覆盖更新，不卸载、不清空应用数据。
2. 打开旧账单，确认账本、分类、金额、账户、退款信息、首页与统计仍正确。
3. “我的 → 同步加密与恢复码”：首次只显示尚未设置；取消生成不会保存。保存恢复码后确认提交。
4. 离线校验恢复码并运行加密自检；错误恢复码应被拒绝，不自动换密钥。重启后密钥应仍可用。
5. 连续修改同一账单，待同步对象计数可合并；删除保留待同步状态。导入、退款及固定收支仍可正常使用。
6. 导出新完整备份，并在准备好回退数据的测试环境检查旧备份恢复。恢复后不会沿用旧队列和密钥范围。
7. 当前无需在服务器操作，不要尝试解除写入锁定或手工上传明文账单。
