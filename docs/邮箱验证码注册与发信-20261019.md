# 邮箱验证码注册与恢复码发信（2026-10-19）

本次没有连接或修改正式服务器，没有发送真实邮件。先配置 163 SMTP 并在后台测试收信，再安装本包，最后使用新 APK。

## 一次性设置发信邮箱

在 163 网页邮箱开启 SMTP，生成客户端授权码。在 PocketBase 后台 Settings 的 Mail settings 填写：

| 设置 | 内容 |
|---|---|
| Sender name | 我的记账本 |
| Sender address / Username | 同一个完整的 163 邮箱 |
| SMTP enabled | 打开 |
| Host | smtp.163.com |
| Port | 465 |
| Password | 163 客户端授权码 |
| TLS | 打开 |

授权码只保存在服务器后台，不要发到聊天，也不要写入手机软件。先用后台测试发信，实际收到后再安装接口。Application URL 保持 https://api.698239.xyz。

## 安装

通过 FinalShell 将解压后的 accounting-mail-code-update 整个文件夹上传到 /root。文件夹内应直接有 deploy-mail.sh、pb_hooks、pb_migrations。

在 FinalShell 终端执行：

```bash
bash /root/accounting-mail-code-update/deploy-mail.sh
```

这次替代旧的 accounting-mail-update 包，不需要先安装旧包。保留已有的加密同步接口；不重建、删除或导入现有账单集合。新增邮件/验证码 hooks 和三项迁移。

脚本会停服备份完整 pb_data、hooks、migrations，再安装并检查服务；会短暂影响同步。SMTP 尚未配置时，登录规则迁移会中止。失败时恢复旧邮件 hooks 并尝试重启，已经成功应用的迁移仍保留；不会擅自恢复整个数据库。终端会显示完整备份位置，请保留。

## 手机里的流程

- 注册：填写邮箱、至少 8 位密码 → 收到邮件 → 回软件填 6 位随机验证码 → 验证成功 → 用刚才的密码登录。
- 中途退出：回注册页填写同一邮箱与原密码，点“验证已有注册邮箱”重新获取验证码。
- 验证码 10 分钟有效，错误最多 5 次，重发后旧验证码立即作废；每账号每类邮件间隔至少 60 秒、24 小时最多 5 次。
- 账号的密码登录保持原样，没有开启免密码 OTP 登录。验证码不作为恢复码使用。
- 原来未验证的已登录用户可在账号或恢复码邮件页面补一次验证码验证。无法登录的旧用户填写邮箱与原密码，点“验证已有注册邮箱”。
- 已验证邮箱以后发送恢复码无需再次验证。收件人只能是当前账号邮箱。
- 手机登录不会开启同步或覆盖本地账单。仍需主动连接加密空间。
- 发信成功只表示 SMTP 已接收，请检查收件箱和垃圾邮件；不保证最终投递。

## 限制与隐私

验证码由服务器生成，仅保存基于服务器秘密的校验摘要、过期时间和尝试次数，不记录明文验证码、密码或邮件正文。失败尝试在数据库事务中提交，服务器重启不会清除限制。确认成功即删除挑战，不能重复使用。邮箱验证门槛在原 users.authRule 基础上追加，保留原权限条件。已验证用户不会因此丢失账单。

公开请求有持久化来源限流；实例每类邮件每天最多 100 次。SMTP 失败也计入限额。来源使用直接连接地址，反向代理下可能共用限制，当前是整个来源 100 次/日、至少间隔 1 秒。未验证注册邮箱必须提供其原注册密码才能重发，防止别人替换密码；忘记密码时需另行使用账号密码恢复流程。

选择“软件发送恢复码”会通过 HTTPS 把恢复码交给记账服务器，再经 SMTP 发到用户邮箱。发信服务器和邮件服务能接触恢复码；不能声称这部分用户的服务器绝无解密可能。界面仍需明确同意。本实现不把恢复码写入 PocketBase 数据表、队列、响应或自己的日志。邮件服务本身可能留存邮件。
