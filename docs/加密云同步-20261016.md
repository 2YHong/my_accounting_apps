## 协议与冲突

业务对象的稳定随机标识替代设备各自的自增主键。导入交易、退款和固定收支期次等逻辑唯一对象使用 HKDF 派生 HMAC 密钥计算不透明标识，使两台设备独立导入同一来源时形成同一对象的分支。密文中嵌套导入快照、固定收支模板/确认记录也转换关联标识。

版本包含 object_uid、revision_uid、parent_uids、epoch、随机 nonce、ciphertext、auth_tag。账单类型、日期、金额、备注、删除含义在加密正文中。认证附加数据绑定用户、空间、对象、版本和父版本。服务器保留追加历史；更新和删除都是新版本。

同一对象有多个图末端时保留全部选择，用户选定后追加以全部末端为父的合并版本。上传前先把密文与版本持久化，响应丢失后重发同一版本；确认只清理精确的本机版本，上传期间的新编辑保持待同步。

收到的密文先解密认证再写入持久游标；历史缺失、顺序回退、同名不同内容会停止。业务写入在一个事务中暂停捕获触发器，并通过原完整备份验证器检查业务约束；关联尚未准备好或父对象仍被引用时延后。编辑页面期间不投影远端业务改动，保证原表单的版本基础不会悄悄变化。

## 约束与后续范围

当前一个账号一个活动云空间、key_epoch=1。每空间最多 50,000 个版本、256 MiB base64 密文累计长度，每账号空间最多 20 个注册设备，每次拉取最多 30 项，每对象最多 64 个父版本。这是当前代码配额，需要结合服务器空间调整。达到配额时保留本机待同步改动，停止新上传。

本轮使用恢复码包，不提供扫码设备互授、设备撤销管理页、根密钥轮换、旧历史自动垃圾回收。X25519 设备公钥持久化用于设备身份配置及后续扩展；当前未把它作为每次 API 的设备签名验证机制，服务权限以 PocketBase 登录用户及设备状态校验为准。GCM 认证由接收设备执行，无法解密的恶意密文会停止同步。

恢复码和原始根密钥不上云；设备本机 SQLite 业务数据仍为原来的存储形式。旧的云备份与明文集合未转换。完整备份恢复会清除云绑定/缓存并旋转安装作用域；重新使用原恢复码连接云空间后，恢复的本地记录与云记录可能形成额外记录或需核对的冲突，请保留原完整备份。
