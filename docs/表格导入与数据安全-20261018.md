# 表格导入、恢复码邮件与数据安全（2026-10-18）

## 本次新增

“我的 → 数据管理 → 账单导入与导出”现在支持以下表头的CSV和Excel（.xlsx）：
类型、金额、日期、分类、标签、描述、账户。

- 类型读取支出、收入；日期支持表格中的年/月/日和时分秒。
- 描述有内容时作为账单标题；空白描述使用原分类名称作标题。
- 默认保留原分类名称，同名同收支类型的分类复用；缺少的分类只在确认导入后创建。关闭“保留表格分类”可统一选择分类。
- 标签和原账户名称保存在备注中。本次没有将标签拆分为软件内的标签关联。
- 默认不关联资产账户，导入历史账单不会改变现有余额。用户主动选择关联账户时，才按收支更新该账户余额。
- 导入前先预览，确认后保存。金额、日期、收支类型异常时，原行进入待核对列表。
- 明确的投资收支继续遵守现有导入规则，跳过并显示原因。
- 该格式没有交易订单号，因此按原始交易字段和相同记录出现次数去重。相同数据再次导入、改文件名或排序不会重复记账；同一文件内两条完全相同的账单仍保留两条。修改交易字段、与其他平台文件交叉导入，或导入以前手工记过的账单，不保证能自动判定是同一笔交易，请核对预览。

提供的样本只用于本地只读验证，没有复制进项目或上传到服务器。305条均可读取，其中298条支出、7条收入，6条空描述使用分类作标题；逐条金额、日期和原分类已核对，再次导入识别305条重复记录。

## 恢复码备份到邮箱

入口：“我的 → 数据管理 → 云同步 → 同步加密与恢复码”。

- 首次生成恢复码的对话框增加“备份到邮箱”。
- 已有密钥时选择“备份恢复码到邮箱”，先输入原恢复码校验，再填写自己的收件邮箱。
- 软件只打开手机邮箱草稿，由用户在邮箱中确认发送。打开草稿不代表已发送，用户应确认邮件已收到。
- 恢复码不经过记账服务器；选择的邮箱服务会保存邮件内容。请只发送到自己的可信邮箱。
- 手机未安装或配置能够处理邮件的应用时，会提示说明，可以继续离线抄写或保存到密码管理器。
- 不会因为打开邮箱草稿，就自动确认密钥保存或覆盖已有密钥。
- 不会在本机明文保存恢复码，也不会将包含恢复码的邮箱启动异常写入日志。
- 使用项目已存在的url_launcher 6.3.2，提升为直接依赖，没有升级其他依赖。

手机邮箱处理方式见[url_launcher官方说明](https://pub.dev/packages/url_launcher)。本次使用模拟邮箱验证界面和草稿内容；安卓、iPhone真实邮箱应用的打开、发送和收信仍需在手机上验证。

## 云同步目前如何工作

先在本机保存账单，再将每个对象的变化加密上传。已连接加密空间时，前台约每30秒同步一次，应用回到前台时也会尝试同步；首次登录的用户仍需主动连接或解锁加密空间。

| 场景 | 当前代码行为 |
| --- | --- |
| 已有本地账单，首次启用同步 | 保留本地账单，上传本地变化并合并云端记录 |
| 新手机已经新增几笔账单 | 新账单与云端旧账单合并，不能因为手机原先缺少云端记录就推断其已删除 |
| 两台手机修改不同账单 | 各自新增或更新的对象可以并存 |
| 两台手机修改同一账单 | 保留冲突分支，等待用户选择；不自动按最后上传者覆盖 |
| 一台删除、另一台编辑同一账单 | 产生编辑与删除冲突；选择删除后会传播该删除 |
| 单纯登录账号 | 登录流程不会清空业务数据库；已经连接过的同一账号可恢复同步状态，随后应用云端变化 |
| 断网或上传响应丢失 | 本地变化和待上传密文保留，可重试；旧上传确认不能清除较新的本地编辑 |
| 无效或不完整的云端数据 | 校验失败则停止；业务表合并在数据库事务内，失败会回滚 |
| 在编辑页面收到云端变化 | 暂缓应用到业务表，避免编辑基于的版本被悄悄替换 |
| 使用“备份与恢复”确认还原完整备份 | 这是有确认提示的整库替换，会替换备份之后新增的本地数据，不是云同步合并 |

本轮用真实的临时SQLite数据库及模拟的云传输验证了：首次同步前B设备已有新增账单、A/B合并、断网重试、冲突选择、无效解密业务数据回滚。没有连接正式服务器，也没有修改用户手机数据库。

普通闪退或中断不等于清空数据库，已提交的数据库事务通常能保留。正在输入但未保存的内容可能丢失。当前测试不能保证所有手机、存储损坏、系统清理、卸载、掉电或大数据量场景都不会丢数据；尚未完成完整的真机故障与压力测试。

## 换手机与恢复码丢失

新手机从云端恢复需要登录原云账号，并用原恢复码解开服务器上的加密密钥包；已授权且仍保存可用密钥的设备可继续使用保存的密钥。

- 恢复码丢失，但旧手机还能正常查看账单：先导出带密码的完整备份，保住这些本地账单。当前版本不能重新显示旧恢复码，也没有“用旧设备重设云端恢复码”的完整功能。
- 还有另一台已授权、能解密的设备：先保留该设备和数据，可从这台设备导出完整备份。
- 所有授权设备密钥和恢复码都丢失：即使服务器密文仍在，管理员也无法代为解密；找回账号密码不能代替恢复码。
- 完整备份文件与它的密码可以恢复文件中包含的数据，但不代表新设备自动获得原云空间的解密密钥。
- 重新生成本机密钥或新恢复码，不能解开另一个原有云空间。
- 恢复码是解密凭据，不能重新生成已经被删掉的账单文件。

## 服务器停用或数据丢失

服务器暂时不可访问时，手机中的本地账单仍可离线使用，新变化等待之后同步；不会因服务器失联而清空各手机数据库。

如果服务商永久删除服务器磁盘，云端数据可能丢失。其他手机只能提供其实际保留的数据；从未下载到这些手机的记录或历史版本，不能凭恢复码找回。

当前没有核实正式服务器的异地备份和恢复演练，不能假定已有灾后恢复能力。正式向更多用户开放前，应完成：

1. 将PocketBase数据库、上传文件、相关配置与服务端程序备份到独立位置，保持账号标识、加密空间、密钥包和版本历史一致。
2. 备份加密保存，保留多个时间点，并监控备份失败。
3. 在另一台临时服务器做完整恢复验证。只在同一台服务器保存备份，无法应对整台机器或磁盘被删除。
4. 完善客户端首次连接前的自动备份、恢复码重新设置与旧设备授权流程。

上面四项是后续工作，不是本次已经部署的功能。

## 注册邮箱

当前PocketBase客户端使用邮箱加密码直接注册，没有自动发送注册验证码或验证邮件。邮箱草稿备份功能也不会证明邮箱归属。正式开放注册前，需要单独配置发信服务并完善邮箱验证、密码找回和对应服务端规则。
