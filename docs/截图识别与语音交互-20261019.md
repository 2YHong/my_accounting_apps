# 本机语音与截图测试版（2026-10-19）

已按最终选择保留 sherpa 中文离线语音，不接入云端 ASR、AI 或收费接口。语音模型和录音数据处理方式保持原样，主要改交互：点一下直接开始准备录音，看到“正在听”和振动后说话；说完点按钮直接核对账单。也支持长按开始、松开结束、上滑取消。启动过程中提前松手不会稍后偷偷打开麦克风，切后台、返回、退出均取消录音。仍以单笔短句为主，最长 30 秒；本次不能承诺长句识别准确率提高。

## 两个版本

- basic：普通版，应用 ID com.example.my_accounting_app，保留原签名，可以覆盖原软件。没有截图模型和入口。
- screenshot：截图测试版，应用 ID com.example.my_accounting_app.ocrtest，桌面名“记账·截图测试”。与原软件并存，数据库、登录状态、密钥与设置各自独立；首次打开数据为空是正常的。
- 两版均使用 release、ARM64、相同版本号和签名。只因测试版的独立名称/标识有极小差异，体积主要差别来自截图模型和功能。
- 请先保留完整备份。若要用相同账单比较，可将同一完整备份恢复到截图测试版；恢复会替换该测试版已有数据，不会替换原软件数据。
- 不需要卸载原软件。

## 截图操作

首页图片按钮 → 系统文件选择器选一张单笔账单详情截图 → 本机识别中英文 → 可编辑识别文字 → 核对账单 → 在原编辑页确认金额、类型、日期、标题、分类和账户 → 保存。

未确认前不会生成账单，不会自动选择银行卡、扣账户余额或上传截图。保存后的账单遵循原来的账户余额联动及加密同步设置。识别原文作为备注保存，原始截图不复制到应用长期目录。不请求整个相册/存储权限。

首版重点支持微信、支付宝等单笔账单详情。识别金额时优先实付/交易金额，排除余额、原价、优惠、单号与时间。多个同优先级金额有歧义时留空让用户填写。外币换算、退款分摊、多笔列表和复杂图片暂不自动处理，请核对。

图片需为 PNG、JPG、WebP。过长拼图、大文件或异常图片会提示裁剪；解码在后台执行并限制像素，避免一次装入巨大位图。当前不能替代真机内存和识别准确率测试。

## 体积依据与构建

直接集成 Google ML Kit 的内置中文模型 text-recognition-chinese:16.0.1，中文识别器包含 Latin/英文能力，无需再装一份英文模型。不使用要求 Google Play 下发模型的版本，也不要求用户下载中文包。

此前 5–10 MB 是参考官方每文字、每架构约 4 MB 加依赖估算，最终以两版实际 APK 为准。实测结果见同目录《两版APK体积与验证-20261019.json》以及交付文件夹说明。APK 体积不等于安装后占用空间，语音首次使用仍会在应用目录准备原有离线模型。

官方来源：
- https://developers.google.com/ml-kit/vision/text-recognition/v2/android
- https://developers.google.com/android/reference/com/google/mlkit/vision/text/chinese/ChineseTextRecognizerOptions

开发命令分别为 flutter run --flavor basic 和 flutter run --flavor screenshot；截图入口直接跟随构建版本，不依赖手动额外开关。iOS 本轮没有新增截图原生实现，也没有构建 IPA。

## 邮箱验证

两版都包含六位邮箱验证码界面。正式服务器需要安装新的 accounting-mail-code-update 并配置 SMTP 后才能测试新注册流程。该服务器更新不影响本机截图识别与语音测试。见《邮箱验证码注册与发信-20261019.md》。

本机 Windows 后续调试可在项目目录运行 `tools\run_android.cmd`（普通版）或 `tools\run_android.cmd screenshot`（截图版）。脚本复用本次 D 盘构建缓存，避免落回 C 盘缺失的编译缓存。D 盘缓存里的代理设置只用于电脑构建；代理端口变动时需更新本机构建设置。
