# Supabase 邮箱登录与个人云同步

本版为个人账号手动加密快照同步：上传替换云端，恢复替换本机。不会自动合并，暂不支持家庭共享。登录和退出不改本机数据库。云账号与本机个人资料分开；本机资料里的邮箱不是登录凭据。每个账号保存一份最新加密快照，最大 8 MB。密码只在操作期间使用，不持久化或上传；忘记密码不能恢复云备份。

## 配置

1. 创建 Supabase 项目，在 SQL Editor 执行 `supabase/setup.sql`。重复执行不会删除已有快照。
2. Authentication 开启 Email 登录和允许注册，邮件模板 Magic Link 使用验证码 `{{ .Token }}`，例如 `<p>你的记账软件验证码：{{ .Token }}</p>`。不使用邮件链接跳转。按实际需要设置验证码有效期和发送限流。
3. 正式使用配置自己的 SMTP；默认邮件服务有收件人和发送次数限制。先用允许的邮箱测试新账号注册、已有账号登录及过期验证码。
4. 获取项目 URL 和 publishable key 或 legacy anon key；绝不能使用 service_role / secret key。应用通过行级权限与验证身份的写入函数访问数据。
5. 在项目根目录创建 `cloud-config.json`（仅填公开客户端配置）：

```json
{
  "SUPABASE_URL": "https://你的项目.supabase.co",
  "SUPABASE_ANON_KEY": "你的公开客户端密钥"
}
```

在 CMD 中执行：

```cmd
cd /d D:\Flutter\projects\my_accounting_app
flutter pub get
flutter analyze --no-pub
flutter test --no-pub
flutter build apk --debug --dart-define-from-file=cloud-config.json
tools\update_android.cmd
```

更新脚本已自动读取项目根目录的 cloud-config.json。配置文件被 Git 忽略；未配置时仍可离线记账。手工构建时每次都需传入配置参数。iOS 在 Mac 上构建时同样传入配置参数，本版已添加 Runner 的 Keychain entitlement，请在 Xcode 检查签名与 Keychain Sharing；真机验证登录持久化后再发布。

## 使用及联调

“我的 → 登录与云同步”：获取邮箱验证码，登录后检查云端，设置至少 8 字符的备份密码并上传。第二台手机用同一账号登录，下载后输入备份密码，核对条数后确认恢复。恢复前先导出本地完整备份。

云端检查只记录待覆盖版本；上传的版本比较由数据库原子执行。两台手机同时检查、依次上传时，第二台应显示冲突，云端保留第一台的版本。冲突后重新检查不会自动合并，需自行确定哪份完整数据应保留。网络中断且上传结果不明确时先检查云端；不要直接重复覆盖。

退出会保留本机全部账单。换人使用同一手机时，另一账号仍能看到本机账单，因此上传前应确认数据归属。登录会话存于系统安全存储，不进入账本完整备份。

需要真机/真实项目验证：首次注册、重复登录、重启会话、离线记账、断网上传、无云备份、错误密码、取消恢复、完整恢复刷新、两手机并发冲突、两个不同账号查询隔离。当前没有真实云项目，SQL 与云端流程尚未部署验证；iOS 未在 Mac 上构建。
